# Track B (Phase 3) 中間報告: 気圧面 → 山頂雲量 の誤差はどこにあるか

作成 2026-09-19 00:30 JST。**数字は全て `backtest/trackb_eval.py` の出力 (`docs/track-b-tables.txt`) から**。
データは取得途中 (00Z ランのみ、ecmwf_ifs025 45 ラン / jma_msm 40 ラン、2026-06-12〜09-17 のうち約 4 割) で、
Single Runs のフェッチ (`python -m backtest.fetch_single_runs --start 2026-06-11 --end 2026-09-17 --hours 0`) を
再実行して埋めれば表は自動で更新される。**Sundqvist 係数の調整・MOS は行っていない。**

## 0. 結論の要約

1. **本体の内挿ロジックの再現は完全一致** (`tests/test_summit_interp.py`: 5 地点 × 384h × 3 変数 × 4 高度、本体 core.py を
   import して同一入力で比較、非 null 値 1 万件超が一致)。以降の数字は本体と同じ計算経路で出している。
2. **① 気圧面 RH の予報誤差 (富士山 3775m, 観測気圧 ≈652hPa で ln(p) 内挿)**: 2026-09-11〜18 の 8 日間、両モデルとも
   **RH を 20〜30 ポイント低く予報** (bias −20〜−32%, MAE ≒ |bias|)。ただしこの期間の富士山は 80% の正時で湿度 100%
   (前線・台風で山頂がほぼ常に雲中) という極端な標本。「点が雲の中」を「格子平均 RH 75%」が表せないという代表性の
   問題が大きく含まれる。ln(p) 内挿と本体の高さ内挿の差は 0.1 ポイント以下 (700→600hPa 間で RH の傾きが小さい)。
3. **②③ RH→雲量→標高内挿の雲量は「ほぼ常に晴れ」に張り付く**: 昼間 (07〜17 JST) の観測所標高/山頂雲量は中央値 0〜7%、
   ≤50% が 85〜94%。観測 (日照 ≥0.4h) の晴れ率 25〜45% に対し、2 値化 (≤50%=晴れ) の適中率は **0.26〜0.42 で
   ベースライン (常に曇り, 0.71〜0.76) を大きく下回る**。見逃し (晴れを曇りと言う) はほぼ 0、空振り (曇りを晴れと言う) が 7 割。
   閾値を 5% まで下げても晴れ判定率が 0.6〜0.7 で観測 0.37〜0.44 を上回る = **スケール自体が観測と合っていない** (閾値の問題ではない)。
4. **比較対象**: MSM の地上全雲量 (`cloud_cover`) はリード 0〜48h で適中率 0.73〜0.77 (ベースライン 0.73〜0.74) と
   唯一まともに判別しており、ECMWF の全雲量は逆に「ほぼ常に曇り」(中央値 98%) で見逃し 0.7。
   `cloud_cover_low` (Open-Meteo が RH から診断) は RH 由来雲量と同じ「晴れ張り付き」傾向。
5. したがって現状の証拠は「**②** (RH→雲量の診断) が誤差の主因で、**①** (RH 予報のドライバイアス) がそれを増幅している」と
   読める。③ (内挿) はこの構図の中では小さい (700↔600hPa 間の RH 差が小さく、内挿法を変えても結果が変わらない)。

## 1. 方法

### 1.1 データ
- 予報: Single Runs API (`backtest/openmeteo_single_runs.py`)。00Z ラン、5 地点同時、1000/925/850/700/600hPa の
  RH / geopotential_height / cloud_cover + 地上 6 変数。900/800hPa は Single Runs では両モデル全 null (api-findings §10.3)。
  → `data/parquet/single_runs_long.parquet` (`parse_single_runs.py`)。派生列 `cloud_cover_at_summit` / `_at_station`、
  `relative_humidity_at_summit` / `_at_station` は本体と同じ内挿 (`summit_interp.py`) で作る。
- 観測: `data/parquet/observation_long.parquet` (`obs_import.py`)。
  - アメダス正時 map (Phase 2, 2026-09-11〜18, 13 地点, temp/humidity/pressure/sun1h/…)
  - 本体リポジトリの既存ハーネスが etrn からキャッシュした毎時値 (2026-06-11〜09-14, 白馬・野辺山・奥日光・菅平・軽井沢・河口湖)。読み取りのみ。
- 時刻: 観測は「HH:00 JST に終わる 1 時間」。予報は T−1h と T の平均を対応させる。

### 1.2 ① の測り方 (富士山)
- 観測: 富士山 50066 の湿度 (直接観測、露点からの換算は不要)、現地気圧、気温。正時のみ。
- 予報: 700hPa と 600hPa の RH を、観測した現地気圧 p_obs で **ln(p) 線形内挿**:
  `RH(p_obs) = RH700 + (RH600 − RH700) × (ln p_obs − ln 700) / (ln 600 − ln 700)`。
  比較用に本体と同じ「geopotential_height で 3776m に線形内挿」も出す。
- 地点気圧 ≈ 652hPa なので重みは ≈0.46 (700 と 600 のほぼ中間)。

### 1.3 ②③ の測り方 (日照との分割表)
- 観測「晴れ」= `sun1h ≥ 0.4h` (既存ハーネスの慣行, 未調整)。昼間 = 07〜17 JST に終わる 1 時間。
- 予報「晴れ」= 雲量 ≤ 50% (未調整)。predictor は 4 種:
  `cloud_cover_at_station` (観測所標高に内挿; **同じ高さで ②③ だけを測る**)、`cloud_cover_at_summit` (製品と同じ山頂値; 麓の日照との比較なので代表性の差も混ざる)、
  `cloud_cover` (地上全雲量, ECMWF はネイティブ)、`cloud_cover_low` (Open-Meteo が RH から診断)。
- 指標: 適中率、空振り率 (晴れ予報のうち曇りだった割合)、見逃し率 (晴れ観測のうち曇り予報だった割合)、
  ベースライン (常に多数派を答える適中率)。全て n 併記。

## 3. 解釈 (①②③ の分離)

- ③ 内挿: ln(p) と高さ内挿の差は 0.1 ポイント未満。700↔600hPa (および麓の 1000↔925) の RH 傾きが小さいため、
  内挿法・目標高度の取り方は結果をほとんど変えない。**③ は主因ではない**。
- ② RH→雲量 (Sundqvist 近似, Open-Meteo 側): 格子 RH 70〜80% では雲量 0〜20% になる。山頂 (点) が雲の中でも格子平均 RH は
  100% に届かない → 診断雲量が構造的に低い。閾値変更で救えない (§2.5)。**② が主因**。
- ① RH 予報: 富士山では −20〜−30 ポイントの乾き。麓では −5〜−11 (MSM) / ±7 (ECMWF)。**① は ② を悪化させる方向**。
  ただし富士山の数字は雲中期間 8 日の標本で、代表性差 (点 vs 格子) を含む。

## 4. 制約と次にやること

- 標本: Single Runs は 00Z のみ・約 4 割取得。12Z と残りのランを取れば n は 2.5 倍。季節は 6〜9 月 (夏〜秋雨) のみ。
- 富士山の湿度・気圧は Phase 2 で毎日貯まる。**晴天日を含む 1 か月分**が揃えば ① の代表性問題を切り分けられる
  (観測 RH が 60% 台の時に予報も 60% 台か)。
- 日照は「雲量 0/1」の代理で、薄い高層雲でも日照は出る。夜間は評価不能。
- MSM 帯の山頂雲量は 900/800hPa 無しの内挿なので本体の実運用値とは違う (ECMWF 帯は同一)。
- 次 (Phase 4 候補): (a) 残りのランを取得して表を更新、(b) 富士山で晴天日が入った時点で ① を再評価、(c) ラジオゾンデ
  (館野・輪島) の RH 鉛直分布で ① を高度別に測る、(d) その上で ② の代替 (全雲量とのブレンド、RH 閾値の再較正) を検討。
  **② の係数をいじるのはこの後**。
