データが貯まったら `parse_single_runs` → `obs_import` → `trackb_eval` を再実行すれば表は更新される。

## 0. 結論の要約 (2026-09-19 時点)

1. **本体の内挿ロジックの再現は完全一致** (`tests/test_summit_interp.py`)。以降は本体と同じ計算経路の値。
2. **2 値化 (雲量 ≤50% = 晴れ) による適中率の比較は結論に使わない (§3 参照)。** 前版の標本は「曇り優勢」(観測晴れ率 0.26〜0.29、
   ベースライン = 常に曇り 0.73〜0.74) で、各予報の適中率は多数派/少数派クラスへの張り付きと区別がつかなかった。
   前版で書いた「② (RH→雲量診断) が主因」という暫定解釈は**保留**にする。
3. **閾値に依存しない評価 (AUC / Peirce skill score, §4) では、RH 由来の山頂・観測所標高雲量は晴れ/曇りを識別できている**:
   山頂値で ECMWF AUC 0.79〜0.81 (95%CI 下限 ≥0.77, lead 0〜72h)、MSM 0.73〜0.79。地上全雲量 (0.73〜0.78) と同等かやや上。
   富士山頂の日照 (7〜8 月, n=530〜583/lead) でも AUC 0.74〜0.76。PSS_max は 0.4〜0.5 で、それを与える雲量閾値は **1〜13%**
   (本体が使う 50% ではない)。
4. **判断 (評価の分岐)**: AUC が 0.5 を明確に上回る → **順序は有効でスケールのみ不正**。次フェーズでは
   分位点マッピング (予報雲量の CDF → 実況晴天率の CDF) を試す。Sundqvist の係数には触れない。
5. **lead 展開 (§4.4)**: 「N 日前の予報は当たっていたか」に対し、山頂雲量 (ECMWF) の AUC は d1 0.80 → d3 0.77 → d5 0.71 → d7 0.61 →
   **d10 0.55 で実用下限 (暫定 0.55) に到達**。富士山頂の実況では **d7 で 0.56 (CI 下限 0.51)** と、2〜3 日早く下限に着く。
   地上全雲量は d10 でも 0.60 で減衰が遅い。MSM は d3 までしか無い。14 日は現データに無い (forecast_days=10 で取得)。
6. **DeLong 検定 (§4.5)**: 麓実況に対する「山頂雲量 0.80 vs 全雲量 0.79」の差は **有意でない** (d1〜3, p=0.13〜0.30)。
   d5 以降は全雲量が有意に良い (p<0.001)。富士山頂の実況では d3 だけ山頂雲量が有意に良い (p=0.02 / 0.002)。
   → 麓実況では「気圧面内挿は地上全雲量と同等 (短い lead) か劣る (長い lead)」、山頂実況では短い lead で内挿優位の傾向。
   本体の単純化 (全雲量に置換) は山頂実況の標本が増えるまで保留、ただし lead 5 日以降で内挿を使う根拠は無い。
7. **分位点マッピングの事前確認 (§7)**: 山頂雲量には**厳密に 0% の塊が麓 4 地点で 16〜29%、富士山で 42〜49%** ある。
   麓は残り 8 割が連続なので破綻しないが、0% 塊は 1 つの確率にしか写像できない (2 段構成が必要)。分割は leave-one-site-out、
   評価は信頼度図 + Brier score (単調変換なので AUC は変わらない)。
8. ① 気圧面 RH の予報誤差 (富士山) は −20〜−30 ポイントの乾きだが、9 月の標本は山頂がほぼ常に雲中 (観測 RH=100% が 80%) で、
   代表性差と区別できない。富士山の日照は夏季 (7〜8 月) のみ観測 (api-findings §10.5) → 山頂で直接 ②③ を測った (§5.2)。
9. **限界 (§8)**: 実況が日照なので**日中のみ**。夜間はひまわり赤外が必要 (Phase 4)。登山者が山頂で経験する精度は富士山頂の 0.75 の方に近い。

## 1. 方法

### 1.1 データ
- 予報: Single Runs API、00Z ラン、5 地点、1000/925/850/700/600hPa の RH / geopotential_height / cloud_cover + 地上変数
  (`fetch_single_runs.py` → `parse_single_runs.py` → `data/parquet/single_runs_long.parquet`)。
  900/800hPa は Single Runs では両モデル全 null (api-findings §10.3) → 内挿は 5 面で行う。
  派生列 `cloud_cover_at_summit` / `_at_station`、`relative_humidity_at_summit` / `_at_station` は本体と同じ内挿 (`summit_interp.py`)。
- 観測: `observation_long.parquet` (`obs_import.py`)。アメダス正時 map (Phase 2, 2026-09-11〜)、既存ハーネスの etrn キャッシュ
  (2026-06-11〜09-14, 白馬・野辺山・奥日光ほか、読み取りのみ)、`jma_etrn.py` で取得した富士山官署時別値 (2026-06-12〜09-17)。
- 時刻: 観測は「HH:00 JST に終わる 1 時間」。予報は T−1h と T の平均を対応させる。昼間 = 07〜17 JST。

### 1.2 ① の測り方 (富士山)
観測湿度 (直接観測) と、700/600hPa の RH を観測現地気圧 p_obs で ln(p) 内挿した予報 RH:
`RH(p_obs) = RH700 + (RH600 − RH700) × (ln p_obs − ln 700) / (ln 600 − ln 700)`。本体と同じ高さ内挿も併記。

### 1.3 ②③ の測り方
- 観測「晴れ」= `sun1h ≥ 0.4h` (既存ハーネスの慣行)。
- predictor: `cloud_cover_at_station` (観測所標高に内挿、**同じ高さで ②③ を測る**)、`cloud_cover_at_summit` (製品値)、
  `cloud_cover` (地上全雲量; ECMWF はネイティブ、MSM も総雲量)。
- **閾値に依存しない指標 (§4)**: ROC AUC (スコア = −雲量、DeLong 法の SE と 95%CI 下限)、Peirce skill score
  PSS = POD − POFD (閾値 50% での値と、閾値を動かした最大値 PSS_max とその閾値)。
- 参考として 2 値化 (≤50%) の分割表も出すが (§3)、上記の理由で結論には使わない。

## 3. 2 値化 (≤50%) の分割表について — ベースラインの定義と、結論に使わない理由

`baseline_acc` = **多数派クラスを常に答えたときの適中率** = max(観測晴れ率, 1 − 観測晴れ率)。

前版 (00Z ラン 45/40 本、観測は麓 3 地点 + アメダス 8 日) では全地点プール・昼間・lead 0〜24h の観測晴れ率が 0.26〜0.27、
つまり **標本の 73〜74% が曇り** で、ベースライン (常に曇り) は 0.73〜0.74 だった。そこで報告した適中率
(RH 由来 0.27〜0.42 = 少数派「晴れ」への張り付き、ECMWF 全雲量 0.76 = 多数派「曇り」への張り付き、MSM 全雲量 0.77 = ベースライン +0.03)
はいずれも張り付きと区別がつかず、**②③ の良し悪しを言える表ではなかった**。

現版 (00Z ラン 98/98 本、富士山夏季日照 774 時間を追加) では観測晴れ率 0.42 (0〜24h, n=3540)、ベースライン 0.58 で、
適中率は `docs/track-b-tables.txt` §B のとおり (RH 由来 0.4〜0.5、全雲量 0.7 前後)。偏りは緩んだが、
50% という 1 本の閾値に依存する評価であることは変わらないので、結論は §4 の AUC / PSS で出す。
表自体は §B に残す (スケールのズレ = 「RH 由来雲量は昼間の中央値 0〜7%」は事実として有用)。

### 4.2 読み方
- RH 由来の山頂雲量 (本体が使う値) の **AUC は 0.79〜0.81 (ECMWF, lead ≤72h)、95%CI 下限でも 0.77 以上** → 晴れ/曇りの順序付けは
  有効。地上全雲量 (0.75〜0.78) と同等かやや上。lead が伸びると 0.61 (168〜240h) まで単調に落ちる = 予報スキルの劣化として自然。
- **PSS@50% は 0.02〜0.17 でほぼ無価値だが、PSS_max は 0.3〜0.5**。差の原因は閾値: PSS_max を与える雲量閾値は **3〜13%** で、
  本体の 50% から大きく外れている。全雲量の方は MSM 50% / ECMWF 90% 前後が最良で、ECMWF 全雲量は「曇り側に張り付く」別方向のズレ。
- 地点別 (§C-2, lead 0〜24h): ECMWF の `_at_station` は 5 地点全てで AUC 0.75〜0.80。**MSM の `_at_station` は白馬 (703m) だけ 0.55** (他 4 地点は
  0.75〜0.81) — 白馬は 1000hPa (≈150m) と 925hPa (≈800m) の間の内挿で、MSM のこの層の RH 由来雲量が谷底の日照と対応していない。
  同じ白馬でも MSM の山頂値 (`_at_summit`, 唐松岳 2696m) は 0.77 なので、低い面固有の問題とみられる (原因は未調査)。
- 標本の注意: 予報は 00Z のみ (98 ラン/モデル)。観測晴れ率は麓 3 地点で 0.24〜0.29 (曇り優勢)、富士山頂 7〜8 月で 0.73 (晴れ優勢)、
  プールで 0.42。AUC/PSS は気候値に左右されにくい指標だが、季節は夏〜秋雨だけ。冬 (乾燥・強風) は未評価。

### 4.3 判断
**AUC > 0.5 (CI 下限含む) → 「順序は有効、スケールのみ不正」の分岐。**
次フェーズの方針: 予報雲量の CDF を実況晴天率の CDF に写像する分位点マッピング (地点 × モデル × lead で層別) を試し、
写像後の PSS@50% が PSS_max に近づくかで評価する。Sundqvist の係数には触れない。
富士山の夏季日照 (山頂で唯一の晴天実況) を取り込んだ結果は §5。

**判定**:
- 麓アメダスを実況にした比較では、**lead 1〜3 日の「山頂雲量 0.80 vs 全雲量 0.79」の差は有意でない** (p 0.13〜0.30)。
  lead 5 日以降は逆に**地上全雲量の方が有意に良い** (差 −0.04〜−0.06, p<0.001)。MSM も day 3 で全雲量が有意に良い。
- 富士山頂の実況では、day 3 だけ山頂雲量が有意に良い (ecmwf +0.07 p=0.02, msm +0.09 p=0.002)。day 1〜2 は +0.03〜0.05 で n=530〜583 では有意に届かず、day 5 以降は差なし。
- **結論**: 麓の実況に対しては「手の込んだ気圧面内挿は地上全雲量と同等 (短い lead) か劣る (長い lead)」。山頂の実況に対しては短い lead で内挿が
  優位な傾向 (day 3 で有意) があり、本体を全雲量に単純化してよいかは**山頂実況の標本が増えるまで保留**。
  ただし「長い lead では全雲量の方が減衰が遅い」は両実況で一貫しており、lead 5 日以降のスコアに気圧面内挿を使う根拠は現状無い。

## 5. ① 富士山 RH と、山頂での ②③ (夏季日照)

### 5.1 ① 予報 RH vs 観測湿度 (§A-1, 9/11〜18 のアメダス正時)
両モデル bias −20〜−32 ポイント、MAE ≒ |bias|。観測は 80% の正時で 100% (山頂が雲中)、予報 RH 平均 71〜76%、≥95% は 1 割。
ln(p) 内挿と本体の高さ内挿の差は 0.1 ポイント未満。**雲中期間に偏った標本なので、乾きバイアスの実在と代表性差 (点 vs 格子) は分離できない。**
富士山の湿度・気圧は Phase 2 で毎日貯まるので、晴天日が入った時点で再評価する。

- 0% 以外は連続 (ユニーク値 1400〜2650 / 3234) だが、**厳密に 0% の塊が 16〜29% (麓 4 地点)、富士山では 42〜49%** ある。
  雲量が 0 になるのは Sundqvist の臨界 RH 未満で診断雲量が 0 になるため。標高が高いほど (格子 RH が低いほど) 塊が大きい。
- 分位点マッピングへの含意: 0% の塊は 1 つの値なので CDF が階段になり、その範囲は「P(晴れ | 予報 0%)」という**1 つの確率**にしか
  写像できない (塊の中で順序付けできない)。麓 4 地点なら塊は 2 割で残り 8 割は連続なので破綻しない。富士山は半分が塊で、
  その半分は 2 値予報に退化する。→ 実装するなら「0% の塊は経験確率 1 点、正の値は分位点写像」の 2 段構成にし、
  塊の割合を地点 × モデルごとに記録して評価に含める。

### 7.2 訓練 / 検証の分割方針 (判断)
- 時系列なのでランダム分割はしない。**leave-one-site-out**: 5 地点のうち 4 地点で写像を学習し、残り 1 地点で検証、を 5 回。
  地点をまたいで使える写像かどうかが本体に載せる上で本質的 (本体は 76 座に適用する)。
- 層別: モデル × lead 日 (1〜3, 5, 7, 10)。季節はデータが 6〜9 月しか無いので当面層別しない (冬は Phase 2 の蓄積待ち)。
- 富士山は「山頂実況」という別種の検証なので、leave-one-site-out の検証側にしたときは別枠で報告する。

### 7.3 評価指標 (判断)
- **分位点マッピングは単調変換なので AUC は定義上変わらない。** 効果は「確率としての信頼性」に出るので、評価は
  **信頼度図 (reliability diagram; 予報確率のビンごとの実況晴れ率) と Brier score (およびその分解: reliability / resolution / uncertainty)**
  で行う。比較対象は (a) 写像前の雲量を 1−雲量/100 で確率とみなしたもの、(b) 気候値 (地点別晴れ率)、(c) 地上全雲量の写像。
- PSS@50% は補助として残す (本体の閾値運用がどれだけ改善するかの目安)。

## 8. 検証の限界 (追記)

1. **日中のみ**: 実況が日照時間なので、評価は全て 07〜17 JST の昼間。**夜間の雲量 (夜明け前の雲海判定、星空) は原理的に検証できていない**。
   夜間を検証するにはひまわり赤外 (雲頂温度) を実況にする必要がある (Phase 4 以降の課題)。
2. **富士山頂 0.75 と麓プール 0.80 の差の解釈**: 後者は麓アメダスの日照を山頂雲量の代理実況にしているため、
   「山頂が晴れ・麓が曇り (雲海)」「山頂が雲中・麓が晴れ」の事例が誤差として混ざる (代表性誤差)。それでも数字が高く出るのは、
   麓の日照と山頂雲量の相関が高い日 (全層晴れ/全層曇り) が多数だから。**登山者が実際に山頂で経験する予報精度は富士山頂の 0.75 に近い**と解釈すべきで、
   0.80 はそれより楽観的。
3. 富士山頂の日照は 7〜8 月のみ (etrn 官署系, api-findings §10.5)。取得経路: `python -m backtest.jma_etrn --station fuji` →
   `data/obs/etrn/fuji/<date>.json` (生 HTML も保存) → `obs_import` (source=etrn_fetch)。
4. Single Runs は 00Z のみ・2026-06-12〜09-17 (夏〜秋雨)。12Z と冬季は未評価。
