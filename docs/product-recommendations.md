# ヤマビヨリ本体への推奨 (提案のみ — 本体は変更しない)

作成 2026-09-19。根拠は `docs/track-b-findings.md` (Track B, Single Runs 00Z 98 ラン × 2 モデル, 2026-06-12〜09-17) と
`docs/track-a-season-tables.txt` (Track A, Previous Runs 1 年分の地上全雲量)。**全て暖候期中心の標本**で、
RH 由来の山頂雲量については寒候期の検証が無い。各項目に「確定」か「暫定 (標本不足)」を付ける。

「確定」の基準: 主要な数字の 95%CI が判定を跨がず、かつ結論が麓実況・山頂実況の両方で同じ向きであること。

---

## R1. 山頂雲量の 2 値化閾値 50% は、診断雲量のスケールと合っていない — **確定 (暖候期)**

- 本体は `cloudcover_at_summit` (Open-Meteo が気圧面 RH から Sundqvist で診断した雲量を山頂へ内挿) を `cloud_penalty()` にそのまま入れ、
  雲海判定等で 50% 前後の閾値を使う。
- 昼間の山頂雲量は中央値 0.5〜20%、厳密 0% が 16〜29% (麓 4 座) / 42〜49% (富士山)。50% 以下が 85〜94%。
- PSS (Peirce skill score) を最大にする閾値は **3〜16% (麓実況)、1〜9% (富士山頂実況)** で、50% での PSS は 0.02〜0.19 (ほぼ無価値)。
  PSS_max は 0.4〜0.5。(findings §4.1, §4.2, §5.2)
- **非対称性 (findings §7.4)**: P(晴れ｜0%) = 0.64〜0.86 に対し P(晴れ｜>50%) = 0.00〜0.01。曇り判定はほぼ外れず、
  晴れ判定が 14〜36% 外れる = **診断の弱点は晴れ側**。登山者に痛いのは「晴れ予報で登ったら雲中」なので、
  確率への写像はスケール合わせであると同時に安全側への補正でもある。
- **写像の効果 (findings §9, leave-one-site-out, 暖候期)**: 「雲量%をそのまま確率と読む」の Brier は 0.40〜0.47 で気候値 (0.24) より悪い。
  写像後は d1〜3 で 0.18〜0.20、PSS@0.5 = 0.4。**地点別 CDF による分位変換は生値ビンの較正と同等** (差 ±0.005) なので、
  載せるなら「生値ビン + 0% 塊の別扱い」の簡単な表で足りる。効果は d7 で消える。
  麓で学習した写像は富士山頂で d7 以降に外れる (0% 塊の晴れ率が山頂では高い) ので、**76 座への一般化は未確認**。
- **推奨**: 山頂雲量を 0〜100 の「雲量%」としてそのままスコアや閾値判定に使わない。順序 (AUC 0.75〜0.81) は有効なので、
  **「晴れる確率」に変換してから使う**。0% の塊は経験確率 1 点 (d1 で 0.64〜0.86、地点依存) として扱う (§7.4)。
  Sundqvist の係数を触る必要は現時点で無い (順序が保たれているため)。
- 状態: **確定** (暖候期・日中) — 「%のままでは使えない」「確率に写像すれば d1〜3 で効く」まで。
  写像の**係数の一般化 (76 座・寒候期) は暫定**。

## R2. lead 依存の予測子選択 — **暫定 (標本不足)**

- d1〜3: 麓実況では山頂雲量 0.80/0.79/0.77 vs 地上全雲量 0.79/0.77/0.76 で **差は有意でない** (DeLong p=0.13〜0.30, n≈3,000〜3,300)。
  富士山頂の実況では d3 で山頂雲量が有意に良い (ECMWF +0.07 p=0.02, MSM +0.09 p=0.002, n=583)、d1〜2 は +0.03〜0.05 (p=0.13〜0.36)。
- d5 以降: 麓実況では地上全雲量が有意に良い (差 −0.04〜−0.06, p<0.001) が、**麓実況は内挿に構造的に不利**
  (麓の天気を測っており、内挿が「山頂だけ曇り/晴れ」を正しく当てても誤りに数える)。富士山頂の実況では d5〜10 の差は −0.01〜−0.02 で
  検出力不足 (n=583, SE 0.025〜0.033) のため判定不能。(findings §4.5)
- **推奨 (暫定)**: d1〜3 は現行の山頂内挿を維持 (山頂実況で優位の傾向)。d5 以降は「内挿を使うべき/やめるべき」のどちらも
  現標本では言えないので、**現行を変えない**。ただし製品として d5 以降の雲量表示に確信度を付ける場合、山頂雲量 (d7 で AUC 0.61、
  富士山頂 0.56) より地上全雲量 (d7 で 0.67) の方が減衰が遅いことは両実況で一貫しているので、
  「d5 以降の参考値として地上全雲量を併記する」は低リスクの選択肢。
- 状態: **暫定**。山頂実況 (富士山 7〜8 月のみ、n≈530〜583/lead) が増えるまで確定できない。

## R3. 雲量ベースのスコアを表示する実用上限 — **暫定 (暖候期のみの標本)**

- 山頂雲量 (ECMWF) の AUC: d1 0.80 → d3 0.77 → d5 0.71 → d7 0.61 → **d10 0.55** (95%CI 下限 0.53)。
- **山頂実況 (富士山頂) では d5 0.64 → d7 0.56 (CI 下限 0.51) → d10 0.55 (CI 下限 0.50)**: 登山者が山頂で経験する精度はこちらに近い
  (麓実況の値は代表性誤差で楽観的、findings §8)。
- 地上全雲量は d10 でも 0.60 (CI 下限 0.58)。Track A (通年) の地上全雲量も d7 で 0.65〜0.67。
- **推奨 (暫定)**: 雲量に基づく「晴れる/曇る」の判定や 0〜100 スコアの表示は **7 日先までを目安**にし、8 日目以降は
  「傾向 (確信度)」に落とす。本体の 14 日表示は、雲量スコアとしては d7 以降で AUC 0.55〜0.61 = ほぼ気候値と同程度、という前提で読む。
  暫定 0.55 を実用下限とした場合、山頂実況では **7 日先で下限に着く**。
- 但し書き: 標本は 2026-06〜09 (暖候期・秋雨) の 00Z ランのみ、実況は日中の日照のみ。寒候期・夜間は未検証。lead 14 日は未取得
  (d10 で 0.55 に達しているので外挿で十分と判断)。
- 状態: **暫定**。

## R4. ECMWF 帯の RH 予報は山頂で乾き側に偏る可能性 — **暫定 (代表性差と未分離)**

- 富士山 (650hPa, 観測気圧で ln(p) 内挿) の予報 RH は観測湿度より −20〜−30 ポイント (n=153〜191/lead, 2026-09-11〜18)。
  ただし観測は 80% の正時で 100% (山頂が雲中) という特異な 8 日間で、格子平均 RH と点観測の代表性差と分離できない。
- **推奨**: 現時点では本体を変えない。Phase 2 で貯まる富士山の湿度・気圧に晴天日が入ってから再評価 (findings §5.1)。
- 状態: **暫定**。

## R5. Single Runs では jma_msm の 900/800hPa が無い — 検証側の注意 (本体への影響なし)

- 本体は MSM 帯で 900/800hPa も内挿に使うが、Single Runs アーカイブには無い。Track B の MSM 山頂雲量は本体実運用より粗い内挿。
  Phase 2 のスナップショット (2026-09-19 以降、7 面付き) で今後は実運用と同じ解像度で検証できる。
- 状態: 事実 (api-findings §10.3)。推奨事項なし。

## R6. 寒候期は未検証 — 適用範囲の但し書き

- Track A (地上全雲量, 通年) では寒候期 (2026-01-15〜02-28, 45 日, n=1,483, 麓 3 地点) の d1〜3 AUC が暖候期より 0.04〜0.06 低い
  (0.73/0.71/0.69 vs 0.77/0.76/0.75)、d5〜7 は差なし (findings §4.6)。ただし lead 方向に単調でない (d3 0.69 < d5 0.72) ので
  **「暖候期より低い傾向があるが確定していない」**。地上全雲量の減衰の形は季節で変わらない。
- **RH 由来の山頂雲量は寒候期のデータが無い** (Single Runs の ecmwf_ifs025 が 2026-04-02 開始)。冬型の下層雲・筋状雲に対する
  Sundqvist 診断の順序性 (R1 の前提) は未検証。
- **推奨**: R1〜R3 を本体に反映するなら**暖候期限定の補正**として実装し、寒候期は Phase 2 のスナップショットが 2026-27 冬を
  越えてから同じ評価 (`trackb_eval`, `tracka_eval`) を再実行して決める。
- 状態: 但し書き (確定事項ではない)。

## R7. 検証できていないこと (本体の該当機能に精度の裏付けが無い)

- **夜間の雲量** (夜明け前の雲海判定、星空): 実況が日照時間なので日中しか検証していない。ひまわり赤外での検証は Phase 4 以降。
- **稜線の風**: 稜線に風の実況が無い (富士山も 2004 年に風の観測終了)。10m 風は Phase 1 で保存済みだが、本体の稜線風とは別物。
- **標高 3000m 級の山頂雲量**: 山頂実況は富士山 (3776m) の 7〜8 月のみ。2500〜3000m 帯の山頂実況は存在しない。

## R8. 「毎時 ≥0.1mm = 降水あり」は、実況では 0.5mm 未満だった時間を 7〜8 割拾っている — 事実は**確定**、閾値の候補は**暫定**

根拠: `backtest/precip_threshold.py` → `docs/precip-threshold-tables.txt` (Track A Previous Runs の毎時 precipitation vs アメダス 1 時間降水量、
麓 4 地点 (白馬・野辺山・奥日光・鷲倉; 富士山は降水観測なし)、2026-01-15〜02-28 + 06-11〜09-17、**全時間帯**、n=10,565/lead)。
実況の「降水あり」= ≥0.5mm/h (アメダスの分解能。実況 0.0 には無降水と 0.5mm 未満の微量の両方が入り、区別できない)。

本体で 0.1mm/h が使われている場所は 2 つで、性質が違う:
- `WET_HOUR_MSM_PRECIP_MM = 0.1` (core.py): 決定論スコアの wet hour 判定。**MSM** の毎時値に対して → MSM はネイティブ 1h なので
  丸めの問題は無い (3h ブロック内一致率 0.04)。
- `ENSEMBLE_PRECIP_WET_THRESHOLD_MM = 0.1` (detail.py): 確信度の wet_fraction と、確信度表の precip_prob / precip_mm。**ECMWF** メンバーの
  毎時値に対して → ECMWF の毎時値は **3h 積算 ÷3 を 0.1mm 丸め** (3h ブロック内一致率 1.00, api-findings §11.2) なので、
  毎時 0.1 は 3h 積算 0.15〜0.44mm を拾う。

**確定した事実 (§P-1, P-3, P-4)**

| model | lead | 予報 ≥0.1 の時間数 / 実況 ≥0.5 の時間数 (bias) | 予報 ≥0.1 のうち実況 0.0 (FAR) | うち予報がちょうど 0.1 の割合 → その実況 0.0 率 |
|---|---|---|---|---|
| ECMWF | d1 | **3.5** | **0.76** | 27% → 0.92 |
| ECMWF | d3 | 3.6 | 0.79 | 26% → 0.89 |
| ECMWF | d7 | 4.0 | 0.84 | 28% → 0.85 |
| MSM | d1 | **2.6** | **0.72** | 20% → 0.85 |
| MSM | d2 | 2.5 | 0.75 | 23% → 0.84 |

- 0.1mm/h で「降水あり」とした時間は、実況で測れる降水 (≥0.5mm) があった時間の **2.6〜4.0 倍**ある。
  実況を T±1h に広げても FAR は 0.59〜0.75 (§P-7) で、タイミング誤差では説明しきれない。
- 予報値は 0.1 に張り付いている: 予報 ≥0.1 の時間の 25〜30% (ECMWF) / 20〜23% (MSM) がちょうど 0.1 で、その 85〜92% は実況 0.0。
  0.2 でも 83〜89% が実況 0.0。**予報 0.1〜0.4mm/h の帯 (ECMWF で予報降水時間の 6 割) はほぼ「実況では測れない」帯**。
  実況 0.0 率が 5 割を切るのは予報 ≥1.0mm/h から (ECMWF d1 0.55、≥2.0 で 0.33)。
- 3h ブロック (ECMWF のネイティブ) で比べても同じ: 3h 積算 ≥0.3mm (= 毎時 0.1) で bias 2.2、FAR 0.64 (§P-6)。
- **本体のスコアへの影響**: wet hour は重み 1.0 でスコアの 50% を占める (`precip_penalty`) ので、この帯の時間は
  「霧雨かもしれない時間」が「雨の時間」と同じ重さで効いている。

**閾値候補 (§P-4, P-6; 暫定)**

| 候補 | ECMWF d1: bias / POD / FAR / PSS | MSM d1: bias / POD / FAR / PSS | 意味 |
|---|---|---|---|
| 0.1 (現行) | 3.5 / 0.84 / 0.76 / 0.48 | 2.6 / 0.72 / 0.72 / **0.47** | 過剰予報。MSM では PSS 最大 (見逃し最少) |
| **0.2** | 2.6 / 0.77 / 0.70 / **0.52** | 2.1 / 0.65 / 0.69 / 0.45 | ECMWF で PSS 最大。ちょうど 0.1 の時間 (92% 実況 0.0) だけ落とす。3h 積算 ≥0.6mm 相当 |
| 0.5 | 1.4 / 0.60 / 0.59 / 0.48 | 1.5 / 0.54 / 0.63 / 0.41 | 「アメダスで測れる降水」に揃える。予報降水時間が 4〜6 割減る |
| 0.7〜1.0 | 1.1〜0.8 / 0.51〜0.42 / 0.52〜0.45 / 0.44〜0.37 | 1.2〜1.0 / 0.49〜0.42 / 0.61〜0.58 / 0.38〜0.34 | bias ≈ 1 だが見逃し 5〜6 割 |

- **推奨 (暫定)**:
  1. **ECMWF メンバーの閾値 (`ENSEMBLE_PRECIP_WET_THRESHOLD_MM`) は 0.1 → 0.2mm/h** (= 3h 積算 0.6mm)。丸め境界 (ちょうど 0.1) の
     時間は 9 割が実況 0.0 で、落としても PSS は上がる (0.48 → 0.52, d1〜2)。確信度の precip_prob 表示も過大が減る。
  2. **MSM の閾値 (`WET_HOUR_MSM_PRECIP_MM`)**: PSS だけなら 0.1 が最良 (見逃しを最も減らす) だが bias 2.6。
     「測れる雨」に揃えるなら 0.5 (bias 1.5, FAR 0.63, POD 0.54)。**どちらにするかは見逃しと空振りのコスト比の問題**で、
     本体はこれまで見逃し側 (唐松岳 9/6) を重く見て調整してきた。ただし唐松岳 9/6 は MSM の mm が 0.0 で moisture rule が拾った事例なので、
     この閾値を上げても参照事例は変わらない。候補: 0.1〜0.4 は重み 0.5、≥0.5 は 1.0 のような段階付け (2 値の実況では検証できないので提案のみ)。
  3. 決める前に必要なこと: 実況側の分解能 (0.5mm) が 0.1〜0.4 の帯を「無降水」と「微量」に分けられないので、**この帯が登山者にとって
     無視できる霧雨なのか小雨なのかは現データでは言えない**。10 分値 (アメダス 10 分降水量は 0.5mm 単位で同じ) でも無理で、
     判断材料は「その帯の時間を wet と数えるとスコアがどう動くか」の方 (本体側で `scratch_past_date.py` の参照事例を再計算して決める)。
- 状態: 事実 (bias 2.6〜4.0、FAR 0.72〜0.84、0.1 張り付き) は **確定** (通年 5 か月、n=10,565/lead、全時間帯)。
  閾値候補 (ECMWF 0.2 / MSM 0.1 or 0.5) は **暫定** (コスト比と実況分解能の問題)。夜間を含む全時間帯の評価なので、
  R1〜R3 と違い日中限定ではない。
