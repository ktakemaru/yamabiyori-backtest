# R1 は冬に害になるか — 暫定検証 (短いリードのみ) と 2027 年 3 月の本格評価計画

作成 2026-09-23。目的: 本体 v1.5.0 は 2026-10-01 以降、学習範囲外の季節で R1 表を使う (product-recommendations R11)。
本体を変えるか (季節制限) を決める材料として、今あるデータで冬の効果を測る。数表は [r1-winter-provisional-tables.txt](r1-winter-provisional-tables.txt)
(`python -m backtest.winter_r1 fetch` → `eval`)。

> **結論の範囲**: この文書の結論は **短いリード (Historical Forecast API の継ぎ足し系列) についてのみ** 成り立つ。
> R1 表の **d1-2 行 (lead 0〜48h) しか検証していない**。**d3 以降の行 (ecmwf d3-5 / d6-10、msm d3-4) は冬について未検証**。

## 1. なぜ Historical Forecast API か

- 当初の指定 (Single Runs) は使えない: Single Runs の `ecmwf_ifs025` は 2026-04-02〜、`jma_msm` は 2026-05-13〜 (api-findings §2.1)。
  2026-09-23 に run=2026-02-01T00Z を再確認し、`ecmwf_ifs025` は HTTP 400 (run not available)、`ecmwf_ifs` (9km) は 200 だが気圧面が 0/48 非 null。
- 旧ハーネスのキャッシュ (`C:/mountain-weather/tools/backtest/cache/`) は `amedas` (実況) だけで予報は無い。
- Historical Forecast API は 2026-01〜02 も気圧面を返す (2026-09-23 実測):
  - `ecmwf_ifs025`: 1000/925/850/700/600hPa あり、900/800hPa は全 null (Single Runs と同じ)。
  - **`jma_msm`: 1000〜600hPa の 7 面すべてあり** (Single Runs では 900/800 が null だった; R5)。→ MSM も同じ方法で評価した。

## 2. データと方法

| 項目 | 内容 |
|---|---|
| 予報 | Historical Forecast API、`ecmwf_ifs025` と `jma_msm`、3 地点の気圧面 (雲量・RH・ジオポテンシャル高度 × 1000〜600hPa)。生 JSON は `data/raw/historical_forecast/` |
| 山頂雲量 | `backtest.summit_interp` (本体 `interp_at_altitude` と同じ; test_summit_interp で一致確認済み)。**主**: 使える面すべて (本体の Forecast API と同じ; MSM は 900/800 も使う)。**感度 2**: MSM を R1 学習と同じ面 (900/800 無し) で |
| 予報値 | 学習と同じ value_h1 (T−1h と T の平均) |
| 実況 | `observation_long.parquet` の麓 sun1h (etrn_cache 優先)。晴れ = sun1h ≥ 0.4h |
| 地点 | 唐松岳/白馬 48141、八ヶ岳赤岳/野辺山 48571、日光白根山/奥日光 41166 (冬の etrn がある麓ペア 3 組。安達太良山/鷲倉は冬の実況が無い) |
| 期間 | 冬 2026-01-15〜02-28 (45 日)。対照: 夏 2026-06-12〜09-17 (98 日、同じ API) |
| 時間 | **主**: JST 07〜17 時に終わる 1 時間 (学習の定義)。**感度 1**: 09〜15 時 (冬でも 1 時間まるごと日が出ている時間) |
| 比較 | 生値 P = 1 − 雲量/100 と、R1 d1-2 行の P (`mos.select_table(..., lead_hours=0)`)。Brier、気候値 Brier (標本の晴れ率)、信頼度表 |
| 不確かさ | ΔBrier = Brier(R1) − Brier(生値) を **日単位ブロックのブートストラップ** (日を復元抽出、2000 回、seed 20260923) で 95% 区間と「R1 が良い」割合 |

### 読むときの注意 (偏りの向き)

1. **R1 に楽観的に偏りうる**。Historical Forecast API は最新の予報を継ぎ足した系列で、実質のリードは d1-2 (0〜48h) より短い可能性が高い
   (継ぎ足し方は API 側の仕様で、この系列からは lead を特定できない)。短いリードでは予報が当たりやすく、表の d1-2 行が想定する状況より
   有利な条件で R1 を試していることになる。**本体が実際に使う d1-2 の後半や d3 以降では、ここでの結果より悪い可能性がある**。
   参考: 夏の対照 (同じ API) の ecmwf は生値 0.414 → R1 0.181 で、Single Runs の d1〜3 の値 (findings §9: 0.40〜0.47 → 0.18〜0.20) に近い。
   夏については短いリードの有利さは大きくないように見えるが、冬について同じとは言えない。
2. **夏の対照は表にとって標本内** (R1 学習と同じ期間・同じ実況)。夏の R1 の成績は上限側の参考値で、冬との差には「標本外であること」自体の効果も含まれる。
3. **麓の日照で山頂を採点している** (代表性誤差)。冬は季節風で山頂が雲の中でも太平洋側の麓 (野辺山・奥日光) は晴れることが多く、
   山頂の晴れを麓の晴れで代用する誤差が夏より大きい可能性がある (未検証; 冬の山頂日照は富士山も無観測)。
4. 07〜17 時の定義は冬には日の出前・日没前後を含む (07 時に終わる 1 時間は冬至付近では日の出前)。その時間は実況がほぼ必ず「晴れでない」ので、
   確率を下げる側の R1 が構造的に有利になる。**冬の判断には感度 1 (09〜15 時) を重く見る**。

## 3. 結果

### 3.1 ΔBrier = Brier(R1) − Brier(生値) (負 = R1 が良い)

| 季節 | モデル | 時間 | 時間数 / 日数 | 晴れ率 | Brier 気候値 | Brier 生値 | Brier R1 | ΔBrier [95% 区間] | R1 が良い割合 |
|---|---|---|---|---|---|---|---|---|---|
| 夏 (対照) | ecmwf | 07-17 | 3232 / 98 | 0.386 | 0.237 | 0.414 | 0.181 | **−0.232** [−0.269, −0.194] | 1.00 |
| 夏 (対照) | msm | 07-17 | 3232 / 98 | 0.386 | 0.237 | 0.284 | 0.185 | **−0.099** [−0.135, −0.063] | 1.00 |
| 冬 | ecmwf | 07-17 | 1483 / 45 | 0.577 | 0.244 | 0.284 | 0.212 | **−0.072** [−0.113, −0.035] | 1.00 |
| 冬 | msm | 07-17 | 1483 / 45 | 0.577 | 0.244 | 0.319 | 0.204 | **−0.115** [−0.161, −0.067] | 1.00 |
| 夏 (対照) | ecmwf | 09-15 | 2056 / 98 | 0.431 | 0.245 | 0.382 | 0.183 | **−0.199** [−0.243, −0.158] | 1.00 |
| 夏 (対照) | msm | 09-15 | 2056 / 98 | 0.431 | 0.245 | 0.258 | 0.201 | **−0.057** [−0.099, −0.016] | 1.00 |
| 冬 | ecmwf | 09-15 | 945 / 45 | 0.694 | 0.212 | 0.187 | 0.200 | +0.013 [−0.035, +0.062] | 0.31 |
| 冬 | msm | 09-15 | 945 / 45 | 0.694 | 0.212 | 0.218 | 0.182 | −0.037 [−0.093, +0.020] | 0.90 |

- 冬も 07〜17 時では R1 が生値より有意に良い。ただし 09〜15 時に絞ると、ecmwf は差が 0 を挟んで点推定はわずかに R1 が悪く、msm も有意ではない。
  夏は 09〜15 時でも両モデルとも R1 が有意に良いので、**冬は短いリードでも R1 の上積みがほぼ消える** (ecmwf: 夏 −0.199 → 冬 +0.013)。
- 冬 09〜15 時の ecmwf は、R1 (0.200) が気候値 (0.212) をわずかに下回るだけで、生値 (0.187) の方が良い。
- 地点別 (07〜17 時): 唐松岳/白馬は冬も R1 が大きく良い (ecmwf −0.165, msm −0.221)。日光白根山/奥日光は差なし (ecmwf −0.003 [−0.070, +0.061]、msm −0.023)、
  赤岳/野辺山は中間 (ecmwf −0.048 [−0.099, +0.001]、msm −0.100)。冬の晴れ率は白馬 0.38 に対し野辺山・奥日光 0.67 (日本海側と太平洋側の差)。

### 3.2 信頼度 (冬、07〜17 時)

- R1 の高い P は冬も合う: ecmwf P=0.737 → 実況 0.774 (n=680)、msm P=0.719 → 0.746 (n=743)。
- **R1 の低い P (曇り予報) は冬に悲観的すぎる**: ecmwf P=0.000〜0.120 → 実況 0.13〜0.43 (n=48〜88 ずつ)、P=0.206〜0.271 → 0.46〜0.48。
  夏は同じ P で実況 0.00〜0.26。冬は「山頂が曇り予報でも麓は晴れ」が多い (§2 注意 3 の代表性の影響と区別できない)。
- msm の低い P (0.071〜0.118) は冬の標本が n=12〜27 と少ない。

### 3.3 MSM の面の違い (感度 2、R11 とは別の事実)

- MSM を R1 学習と同じ面 (900/800hPa 無し) で内挿すると、R1 の上積みは夏 −0.165・冬 −0.153 と、本体と同じ面 (900/800 あり) の −0.099・−0.115 より大きい。
  夏の信頼度も、900/800 ありでは R1 が晴れを低く見積もる (P=0.511 → 実況 0.693)。
- つまり **R1 の MSM 行は「900/800 無しの山頂雲量」で学習されたが、本体は Forecast API で 900/800 も使って山頂雲量を作っている** (学習と運用の入力の違い)。
  季節とは別の問題なので、本体への推奨としての整理 (R 番号を付けるか) は判断待ち。

### 3.4 標本は判断に足りるか

- 冬は 45 日 × 3 地点、約 1,480 時間 (09〜15 時は 945 時間)。ΔBrier の 95% 区間の幅は ±0.04〜0.06。
- **「短いリードで R1 が大きく悪い (ΔBrier が +0.06 を超える)」は否定できるが、それより小さい悪化は判定できない**。
  地点別では区間がさらに広く、地点差の判断には足りない。d3 以降は標本自体が無い。

## 4. 2027 年 3 月の本格評価の計画 (README 待ち項目 #2 に対応)

目的: 暖候期表の冬への適用 (本体の現状) をリード別に評価し、必要なら寒候期表 (`season.label = "cold"`) を作る。

1. **データの確認 (2027-03 上旬)**: `python -m backtest.check_collection --days 30` と、`data/snapshots/forecast/` の 2026-12-01〜2027-02-28 が
   2 モデル × 収集スロットでそろっていること、`meta_before`/`meta_after` (ランの初期時刻) があること、同期間の `data/obs/amedas/` の麓 4 局の sun1h。
   欠けは埋められない (アメダス 8 日・Ensemble 4 日しか遡れない) ので、欠けの範囲を記録するだけ。
2. **スナップショット → long Parquet**: `parse_single_runs.py` に倣って `(site, model, fetched_at, run_init, valid_time, variable, level, value)` を作る
   (新規スクリプト。Forecast スナップショットは 900/800hPa を含む = 本体と同じ面)。山頂雲量は `summit_interp` で。
3. **lead の扱い (R11)**: 2 通りで数え、両方の結果を出す。
   - (a) **本体の数え方**: 取得日 (fetched_at の JST 日付) を 1 とする暦日差。本体 v1.5.0 が実際に引く行で R1 を評価する (本体の現状の実害の測定)。
   - (b) **学習の数え方**: `meta_before`/`meta_after` の `last_run_initialisation_time` をそのスナップショットのランとみなし、lead = valid − 初期時刻 (時間)。
     継ぎ足し (api-findings §10.1) のため、最新ランのホライズンを超える時刻は古いランの値なので **(b) の対象から外す** か別集計にする
     (実測のホライズン, api-findings §2.1/§10.1: ecmwf_ifs025 00Z 363h・06Z 147h (12/18Z は未確認)、msm 00/12Z 79h・03/06Z 40h・09Z 39h (他は未確認))。
   - (a) と (b) の差が R11 の実測値になる (r11-lead-mismatch.txt の仮定別の数え上げを置き換える)。
4. **評価**: モデル × lead 群 (表の行と同じ: ecmwf 0-48 / 48-120 / 120-240h、msm 0-48 / 48-96h) × 時間帯 (07-17 と 09-15) で、
   本文書と同じ指標 (Brier 生値 / R1 / 気候値、信頼度表、日単位ブロックのブートストラップ)。予報値は value_h1。
   本文書の短いリードの結果と、(b) の lead 0-48h の結果が整合するかを最初に確認する。
5. **寒候期表の候補**: `cloud_calibration_table.build()` と同じ手順 (ビン・PAV・lead 束ね) を冬の標本で回し、`mos_export` で
   `season = {"label": "cold", "months": [12, 1, 2]}` の表セットを作る (表セットの版を上げる)。暖候期表との差と、leave-one-site-out の成績で採否を判断。
   MSM は 900/800 ありの山頂雲量で学習し直す (§3.3)。
6. **標本の見込み**: 90 日 × 麓 4 局 (鷲倉を含む) × 11 時間 ≈ 4,000 時間 / lead 群。区間の幅は本文書の約 0.6 倍 (±0.03 程度) の見込み。
   富士山頂は冬に日照が無いので山頂実況での確認はできない (代表性の問題は残る)。
7. **本体への反映の判断**: 結果を product-recommendations に新しい R 番号で記録し、mos の `on_mismatch` (allow / passthrough) と寒候期表の採否を決める。

## 5. 10 月 1 日の判断材料 (判断基準に照らして)

判断基準は「短いリードで R1 が生値より悪い → 季節制限を検討 / 悪くない → 現状維持し既知の制約として明記」。短いリード (Historical Forecast API、
d1-2 行のみ) の冬 (2026-01-15〜02-28、麓 3 局) では、R1 が生値より有意に悪いという結果は出なかった。学習と同じ 07〜17 時では両モデルとも R1 が有意に良く
(ΔBrier ecmwf −0.072、msm −0.115)、日の出前・日没前後を除いた 09〜15 時では ecmwf +0.013 [−0.035, +0.062]、msm −0.037 [−0.093, +0.020] で、
どちらも差は 0 と区別できない。したがって基準に照らすと **「悪くない」→ 現状維持し、既知の制約として明記** に当たる。ただし制約として書くべき点が 3 つある:
(1) 冬は短いリードでも R1 の上積みがほぼ消える (特に ecmwf の日中)、(2) 曇り予報のときに R1 は冬の実況より悲観的 (P ≤ 0.12 で実況 13〜43%)、
(3) この結論は短いリードのみで、R1 に楽観的に偏りうる条件で得たもので、d3 以降の行は未検証。標本は大きな害 (ΔBrier > +0.06) を否定するには足りるが、
小さな害は判定できないので、2027 年 3 月の本格評価 (§4) で置き換える。
